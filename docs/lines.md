# Линии: упрощение, классы и бюджет вершин

Линии на карте показываются на любом zoom. Упрощение геометрии — всегда; классы (PostGIS) дают LOD и приоритет бюджета.

## Переменные

- `GIS_MAX_LINE_VERTICES=5000` — максимум вершин во всех `LineString` одного ответа после упрощения. Если бюджет превышен — целые линии отбрасываются. При наличии классов сначала укладывается `backbone`, затем всё остальное (без разделения br/access). `0` отключает бюджет (не рекомендуется на мобильных).
- `GIS_LINE_SIMPLIFY_METERS` — таблица допусков упрощения (Douglas–Peucker), метры. Формат: список пар `zoom:meters` через запятую, по возрастанию zoom.
- `GIS_LINE_CLASSES_BY_ZOOM` — LOD классов линий (PostGIS). Формат: `zoom:mode,...`, mode = `backbone` | `all`. Берётся пара с наибольшим `zoom` ≤ текущего zoom карты.

Правило выбора допуска simplify: берётся пара с наибольшим `zoom`, не превышающим текущий zoom карты. `meters=0` — без упрощения.

## Стартовая таблица simplify (для опыта, крутить в `.env`)

| Zoom (порог) | Допуск | Смысл |
|---|---|---|
| 0 | 50 м | обзор города/района, грубый рисунок сети |
| 12 | 20 м | кварталы |
| 14 | 8 м | улицы |
| 16 | 2 м | почти трасса |
| 18 | 0 | без упрощения |

```env
GIS_LINE_SIMPLIFY_METERS=0:50,12:20,14:8,16:2,18:0
```

## LOD классов (PostGIS)

После classify (`feature_classes`) на малых zoom отдаём только магистраль:

| Zoom (порог) | Mode | Смысл |
|---|---|---|
| 0 | backbone | обзор: только backbone |
| 13 | all | деталь: все классы |

```env
GIS_LINE_CLASSES_BY_ZOOM=0:backbone,13:all
```

Порог `13` совпадает с границей после simplify-порога `12` (обзор → кварталы/деталь). В `gis`-режиме классов нет — LOD не применяется.

## Порядок обработки на backend

1. Ответ GIS / PostGIS → оставить только Point / LineString.
2. Сэмпл точек при малом zoom.
3. **PostGIS:** фильтр линий по `GIS_LINE_CLASSES_BY_ZOOM` (SQL EXISTS на `feature_classes`).
4. **До упрощения** оставить ограниченный набор линий (`≈ GIS_MAX_LINE_VERTICES / 4`): сначала backbone, потом остальное.
5. Грубая нарезка вершин (stride) + при необходимости Douglas–Peucker / `ST_Simplify`.
6. Бюджет вершин на весь ответ: backbone → остальное; лишнее — отброс целых линий.
7. Клиент: сначала точки, затем линии (сначала не-backbone, потом backbone поверх, толще).

Пороги крутятся в `.env` без пересборки образа при монтировании в backend. После смены — перезапуск API.
